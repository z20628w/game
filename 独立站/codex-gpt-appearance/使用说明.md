# GPT 银白龙娘 · Codex 外观

本地个人定制：银白龙娘头像、墨绿星空背景、12 秒启动动画。启动完成后，背景以 30% 强度保留，龙娘会周期性眨眼、发丝小幅轻摆。

## 启用

双击桌面 `Codex Animation` 时按窗口状态处理：

| 当前状态 | 入口行为 |
| --- | --- |
| Codex 完全退出 | 启动应用，播放 12 秒开场动画 |
| Codex 在后台，主窗口已关闭 | 恢复原窗口，播放约 1.5 秒闭眼到睁眼的过渡；不重启应用 |
| 主窗口仍开着，包括最小化 | 只置前或还原窗口，不重播动画 |

动画中按 `Esc` 可跳过。首次从官方图标启动的实例没有外观接口时，仍需保存工作后确认重启一次；后续通过动画入口运行的实例可以直接复用。

后台恢复动画使用 45 帧、30 帧/秒的连续眼睑动作：约 0.18 秒闭眼、0.75 秒睁眼；从第 0.54 秒起整个动画层逐渐融入工作界面，睁眼与界面显现重叠，总时长为 1.5 秒。覆盖层完全透明后才移除，避免先变暗再突然切换。完整退出后的开场仍为 12 秒；窗口已打开或最小化时仍只置前。

`assets/eye-open-motion.webm` 保持原画尺寸，使用局部眼睑纹理形变产生连续中间姿态，背景和人物位置固定；先解码并暂停在闭眼首帧，窗口显示后再播放。`preview/睁眼动画.gif` 是同一套动作的循环预览。程序使用无声 WebM 以精确控制暂停与起点；不支持解码、自选图片或系统减少动态效果时回退到原图过渡。素材构建命令为 `node tools/build-eye-motion.mjs`，需要项目 Playwright 浏览器与 FFmpeg。

睁眼画面在后台准备时就随窗口尺寸自动适配，播放时不再重新计算图片大小，避免恢复窗口后首帧从小到大的跳动。

恢复动画开始前会等待背景图片解码、动态纹理上传和首帧绘制完成；最多等待 2 秒，慢解码则回退到静态背景。转场期间动态背景保持初始睁眼姿态，动画结束后发丝摆动在约 0.8 秒内逐渐增强，避免交接时人物突然换姿态。恢复动画本身为 1.5 秒。

后台恢复时还会先启用原生窗口显示保护，闭眼画面完整覆盖视口并完成合成后才解除保护，避免 Windows 先闪出上一次的工作界面。首帧合成结果只在内存中使用，不保存截图。恢复失败会解除保护，辅助进程另设 45 秒兜底；窗口已打开或最小化的分支不经过此流程。

为减少点击后的等待，启动入口优先使用 `PortOwner.exe` 直接核对本机监听端口及官方进程路径，保留错误进程与公开监听拒绝规则。后台恢复在显示保护生效后先唤醒窗口，再加载视频，避免隐藏页面限制解码。播放被可见性切换暂停时，过期的播放取消不再触发图片回退。运行目录 `%LOCALAPPDATA%\OpenAI\ChatGPTFix` 下的 `reopen-timing.json` 记录各阶段耗时，`background-launch.json` 记录脚本总耗时；这些记录不包含聊天内容。

此处借鉴社区 R16 的预热与一致边界画面思路，使用本项目现有图片和 WebGL 实现，未复制其代码或媒体：<https://github.com/HanwenZhang-George/codex-startup-animation/blob/main/community-v34/src/FilmSplashV2.cs>。

重启会中断正在运行的任务，尚未发送的输入可能丢失。启动器只会在你点击“是”后，关闭官方 Codex 安装路径对应的进程。你也可以先自行从托盘完全退出，再打开动画入口。

修改头像、背景、字幕和透明度：按 `Ctrl+Alt+B`，或者双击桌面 `Codex Image Settings`。必须已经通过动画入口启动 Codex，设置入口才能连接。

图片设置新增“动态背景：龙娘眨眼与发丝轻摆”开关。默认开启，约每 5.6 秒眨眼一次，发丝采用局部轻微形变，背景渲染限制在约 30 帧/秒。窗口隐藏、页面被系统判定不可见或系统开启减少动态效果时暂停。开场动画期间也暂停日常背景，结束后恢复。自选壁纸维持静态，避免把龙娘的眨眼位置错误应用到其他图片。图形能力不可用时回退静态图。

不想使用时，在图片设置中选择“关闭美化，恢复 Codex 外观”。长期停用则完全退出后使用官方原入口。此安装不添加 Windows 登录自启动任务。

请保留此文件夹；桌面快捷方式依赖它。移动目录后需要重新运行 `tools/install-windows.ps1`。官方应用更新后若无法启动，可使用官方原入口，再检查此启动器兼容性。

## 实现与验证

启动器不修改官方安装包，通过绑定 `127.0.0.1` 的空闲端口临时载入动画和背景。端口自动选择并保存在 `%LOCALAPPDATA%\OpenAI\ChatGPTFix\runtime-port.json`，图片设置入口读取同一记录。只有校验监听进程为官方 Codex 后才连接；忽略系统返回的 PID 0 残留记录。该接口可控制本机应用页面，请勿转发端口或开放到网络。关闭 Codex 后该接口关闭。重复点击启动入口不会同时启动多个重启流程。

2026-11-02 已检查官方 Store 包 `OpenAI.Codex_26.1027.3384.0_x64__2p2nqsd0c76g0`，内置 Node 运行环境可用，启动辅助程序编译通过。

验证：项目现有测试 6 项通过；独立 Chromium 宿主中验证了预热、完整播放、背景保留、30% 默认强度、自定义文字、恢复原外观与 Esc 跳过，页面异常 0。结果见 `preview/verification.json`，画面见 `preview/01-avatar.png` 与 `preview/02-wallpaper.png`。

当前聊天期间没有退出或重启 Codex，因此真实客户端冷启动和当前客户端界面的背景适配仍需首次通过桌面动画入口启动确认。以上浏览器验证不等同于真实客户端验证。

2026-11-02 后续修复：用户实机遇到端口归属错误。检测发现 NetTCPIP 返回 PID 0 的残留记录，同时真实临时监听端口的 State 字段可能为空。因此查询改为按本地端口、远端端口 0、真实 PID、回环地址和程序完整路径校验，不再依赖 State 过滤。启动时动态选择空闲端口，校验通过后才启动页面连接，使用互斥锁防止重复启动。已通过真实临时回环监听测试，以及残留记录、错误进程、非回环地址、取消重启等回归测试；未主动重启当前聊天验证冷启动。
