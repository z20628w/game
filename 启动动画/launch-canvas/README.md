# 启幕

使用 TypeScript + Electron 制作的 Windows 软件启动动画与背景管理器。安装程序为 `release/1.8.0/LaunchCanvas-Setup-1.8.0.exe`，由你手动运行，可以选择安装目录。安装包包含 Electron 运行环境、原生窗口助手和内置素材，无需另外安装 Node.js。

各版本分别保存在 `release/<版本号>/`。后续打包会依据 `package.json` 的版本号自动输出到对应文件夹，安装程序、配套 blockmap 和解包运行目录放在同一版本下，其他版本的归档予以保留。

1.8.0 将已验收的 5 套主题升级为连续视频：银白龙娘经典原版、ChatGPT 翡翠花园（插画）、ChatGPT 银白龙娘（二次元）、Claude 暖阳书阁（插画）、极光雪境。每套包含约 8.3 秒冷启动、约 3.3 秒恢复和约 5.8 秒循环背景，共 15 段视频，已随安装包提供，播放无需联网或生成额度。其余 28 套继续使用原有效果，本次为分批更新。

在「主题图库 → 连续视频」筛选中选择主题，点击「应用整套」并保存，可使用同套素材的连续衔接。已经绑定这 5 套主题的软件组会自动使用新视频，保留安装路径、开关、显示方式及背景显现程度；用户导入的素材保持原设置。新视频按原速完整播放，避免旧时长配置将动作截断或加速；动画结束后可继续播放循环背景等待软件就绪，并在交接时匹配背景相位和应用底色。已打开窗口再次置前时保持背景当前进度。

升级前从托盘退出启幕，手动运行本版安装程序，安装到原目录即可。内部背景仍仅对已经确认适配的 Codex 和 WorkBuddy 开放。播放器与窗口交接已用独立测试程序验证，真实软件更新后的显示仍以本机效果为准。

1.7.6 修复通过启幕打开 Codex 后任务栏出现白色文件图标的问题。带背景参数直接启动 Store EXE 时，进程未取得包身份；现在按官方安装清单，为已核验归属的主窗口设置官方任务栏应用身份、图标和重新启动命令。冷启动、后台恢复、已打开窗口置前以及动画交接时均覆盖；同一窗口不重复设置。任务栏重新启动命令仍进入启幕的软件组，以保留动画与背景。只修复已确认的官方 Codex，不改其他软件、目标安装文件、进程或窗口原有图标句柄。

验证：`tests/taskbar-icon.cjs` 在独立 Windows 窗口检查身份与图标设置、错误窗口归属拒绝、无效图标拒绝及原进程保留。本机当前 Codex 已不经重启修复，用户确认任务栏图标恢复。实现遵循 [Microsoft 的任务栏图标与窗口身份规则](https://learn.microsoft.com/en-us/windows/win32/properties/props-system-appusermodel-relaunchiconresource)。

1.7.5 修复 Codex 自动更新后背景被误判禁用，以及 WorkBuddy 首页遮住已加载背景的问题。根据当前用户官方 Store 安装记录，在执行背景策略前迁移旧版 Codex 的入口、窗口程序与文件说明；即使旧包还在也跟随更新，选择旧安装目录时同样转到当前版本。人工绑定其他程序的窗口不会被迁移。软件组 ID、素材及开关状态保留；若旧版已经自动关闭了 Codex 背景，请在「软件背景」重新打开开关。

WorkBuddy 新增已核验的首页主容器适配，输入框、弹窗仍保持原有底色。窗口已经打开或最小化时，点击启动软件会直接置前并应用启用的背景，不播放动画；缺少本次运行的背景接口时明确提示保存目标软件中的工作、完整退出后从启幕启动。背景接入异常不能记为验证通过。其他软件的背景仍统一禁用。升级时从托盘退出启幕，手动安装到原目录。

验证：`tests/background-policy.test.cjs` 覆盖 Codex 旧包残留、旧包删除、目录重选与错误绑定；`tests/background-smoke.cjs` 覆盖 WorkBuddy 首页背景、输入框与弹窗底色、背景还原，以及独立测试软件窗口置前时的背景应用与缺少接口提示。真实软件安装身份只读核验，测试不强制退出真实软件。

1.7.4 修正桌面入口：发送到桌面的软件组使用目标软件图标，启动器与窗口程序分离时优先使用实际窗口程序图标。升级后启动启幕会更新属于当前安装的已有软件组入口，保留名称、启动参数与动画配置。启幕的桌面／开始菜单名称、卸载列表名称、窗口标题和托盘提示统一为「启幕」；内部程序文件名及数据目录保持兼容。安装器沿用原安装记录迁移旧名称。

1.7.3 修复 WorkBuddy 等软件通过菜单退出后立即重开，却仍播放恢复动画的时序问题。软件退出时旧进程可能尚未收尾，甚至与新主进程短暂重叠；旧版只检查是否还有主进程，未必能观察到「没有进程」的间隙。现在在动画显示前再次核对实际主窗口所属进程，若已不属于原后台实例，则销毁隐藏预热的恢复播放器、改播冷启动。原后台实例恢复窗口仍使用恢复动画；校准中的恢复验证遇到新进程会明确提示不能计为恢复成功。诊断日志增加最终窗口进程与动画类型。

`tests/restart-regression.cjs` 使用独立测试程序模拟旧进程继续存活、新进程已经创建窗口的重叠时序，检查真正显示的只有冷启动动画，同时覆盖正常后台恢复、残留辅助进程、退出竞争、隐藏窗口与完全退出重启。真实 WorkBuddy 仅只读核对生命周期日志，没有为测试关闭用户实例。

1.7.2 将内部背景改为启幕内置确认名单：目前只有 Codex 与 WorkBuddy 开放，其他软件（包括 DoubaoWork、HBuilderX 和通用 Electron 软件）全部禁用背景，不再显示「背景待验证」。扫描框架、窗口校准成功、重命名软件组、导入配置或新增适配 JSON 都不能授权背景。Codex 核对官方 Store 安装路径；WorkBuddy 核对实际 EXE 名称、文件版本中的产品与厂商信息以及应用包结构。名单与确认过的页面规则随启幕程序发布，未来新增软件必须完成单独适配和验证后再开放。

升级时自动关闭其他软件旧配置中的背景开关，保留冷启动、恢复动画、素材选择与快捷方式。界面禁用背景开关、编辑、预览和校准验证；保存与实际接入时也重新核对名单。未确认软件不再自动附加背景调试参数。对于旧版本已接入的背景，优先经归属验证的本机接口撤销；如果旧接口不可用，请正常退出对应软件后重新打开以清除旧画面。启幕不会强行结束目标进程。已确认名单表示启幕已有适配，运行时连接仍需校验，软件升级也可能要求更新适配。

`tests/background-policy.test.cjs` 覆盖改名、伪造标记、导入、换绑以及保存／接入拦截；`tests/electron-restart.cjs --gallery` 验证旧配置迁移和未确认软件禁用背景后仍能冷启动／恢复，且不添加背景调试参数；`tests/background-smoke.cjs` 以只读确认的 WorkBuddy 安装身份在独立测试页面验证背景渲染，不操作用户真实窗口。

1.7.1 修正首次添加软件时校准向导的操作提示。进入第二步即明确显示「软件组与窗口绑定已保存」，无需返回启幕主页面再次保存。软件仍打开时可先验证直接置前，冷启动和后台恢复按钮分别说明正在等待的状态；冷启动要求保存的是目标软件中未保存的文件，而不是启幕配置。回到向导时刷新状态，也可手动刷新。验证可以分次进行，点击「完成」会保留已有绑定，未执行项仍显示待验证。首次选路径、自动进入校准、保存绑定及跳过验证的完整流程已加入 `tests/calibration-wizard.cjs`，界面记录为 `preview/calibration-onboarding.png`。

1.7.0 新增窗口校准向导。新建软件组后可直接校准；已有软件在「适配与文件绑定 → 窗口校准向导」进入。扫描当前可见或最小化的顶层窗口，依据完整程序路径、本次启动的进程链和安装目录提供推荐。用户确认后，保存真实窗口 EXE 与窗口类型；启动入口、软件组 ID、素材和快捷方式保留。同一程序有多个匹配窗口时，需要补充稳定标题片段。不会把整个安装目录的进程都计作目标软件，也不将独立启动器提前退出误认为主窗口退出。

冷启动、后台恢复、直接置前、内部背景分别验证和记录结果。目标软件需要关闭窗口或完整退出时，由用户保存工作并手动操作；向导不会强杀进程。前置状态不符合时提示调整，不能把一次置前当成冷启动成功。验证结果保存在启幕自己的运行目录，修改相关绑定或素材设置后旧结果失效；只换素材不要求重新选择窗口。软件更新后建议重新校准。窗口校准不会赋予内部背景能力，DoubaoWork 当前仍显示背景「未支持」。已有背景适配的软件，可单独验证接口归属与背景加载，最终视觉效果仍需用户确认。

本版验证包括 `tests/calibration-wizard.cjs` 的独立启动器与真实 Windows 窗口流程、多窗口歧义、窗口关闭后拒绝旧选择、保留素材、三种启动行为及验证记录失效；`tests/electron-restart.cjs --gallery` 覆盖 Electron 背景独立验证及原有启动／恢复回归。测试只操作独立测试程序。结果与界面截图位于 `preview/calibration-wizard.json`、`preview/calibration-select.png`、`preview/calibration-results.png`。

1.6.2 修复 DoubaoWork 等独立启动器软件已打开却误报主进程退出、反复播放冷启动的问题。启动入口与窗口监测程序分别绑定：检测到入口文件的启动器标识，以及 `app` 或 `bin` 下唯一的同名 Chromium 主程序时，启动仍使用入口，窗口和进程状态改为监测实际主程序的完整路径。Chromium 渲染、GPU、崩溃处理等辅助进程不算作主进程；该识别不代表支持内部背景。升级后自动修正符合条件的旧绑定，保留软件组、动画设置与桌面快捷方式。「适配与文件绑定」可查看两个路径。更新时从托盘退出启幕，再手动安装到原目录。

已对本机 DoubaoWork 安装结构及实际窗口归属进行只读核验。`tests/launcher-bridge.cjs` 使用独立测试软件验证启动器退出、窗口置前、后台恢复、残留辅助进程和旧配置迁移，结果为 `preview/launcher-bridge.json`；不结束用户正在运行的软件。其他安装结构可通过适配 JSON 单独指定窗口程序，不会将整个安装目录内的进程都视为目标软件。

1.6.1 统一冷启动和恢复动画的窗口尺寸：先保护目标窗口，在后台启动或恢复软件，取得本次主窗口稳定的真实边界后，再按相同位置和大小显示动画。历史尺寸仅用于隐藏状态的预热，不再显示默认 1000×650 或过期缓存尺寸。动画期间跟随窗口移动、缩放和最大化，交接前再次校正；外层覆盖完整软件窗口，内部画面对齐客户区，避免标题栏与边框造成背景取景跳变。首次启动需等软件创建主窗口后才出现动画，因此出现时间取决于目标软件自身启动速度。原有的已打开／最小化窗口直接置前逻辑保留；独立图库预览仍使用预览窗口。

`tests/window-geometry.cjs` 使用独立 Electron 测试软件验证首次冷启动、播放中移动缩放、恢复时尺寸与历史不一致、冷启动最大化及最小化置前。`tests/warm-handoff.cjs` 追加客户区尺寸改变后的末帧逐像素对齐检查；`tests/electron-restart.cjs --gallery` 验证真实启动、恢复、退出重启和背景接入。结果分别保存在 `preview/window-geometry.json`、`preview/warm-handoff.json` 和 `preview/electron-restart.json`。

1.6.0 将 32 套图库冷启动分别编排为 32 个演出：同一 AI 的两种画风也分别使用不同动作。保留整幅人物构图，以书页翻转、双光交汇、声呐定位、卷轴展卷、月相演变、引力盘、根茎生长、折纸启航、知识图谱、唱片与拨弦等物体和场景动画完成开场。人物不再进行局部网格拉伸；也不再统一套用碎片重组、描线显色或揭图遮罩。原版银白龙娘的经典动画继续单独保留，恢复动画和背景未改变。默认仍为 12 秒，保存的时长和图库绑定不变，升级后自动使用新演出。

本版属于程序绘制的主题动态图形，不是新生成的人物逐帧动画。最后一帧回到对应图库背景首帧；目标软件的窗口内容与背景透明度仍由原有适配负责。网络参考、全部分镜对应表与实现边界见 [冷启动设计参考](docs/冷启动设计参考.md)。样片入口为 `preview/cinematic/index.html`，逐套截图和验证记录也在该目录。更新时先从托盘退出启幕，再手动安装到原目录。

## 安装后使用

1. 运行安装程序，按中文向导完成安装。
2. 打开「启幕」。如果检测到官方 Store 版 Codex，会建立默认的「Codex · 银白龙娘」软件组。
3. 分别选择「冷启动动画」「恢复动画」「软件背景」，更换本地素材、调整时长或背景显现程度，再保存配置。
4. 点击「发送到桌面」，以后通过对应软件组的桌面快捷方式启动。修改软件组后不必重建快捷方式。
5. 添加其他软件时，选择安装目录或 EXE，检查检测结果及主程序，也可导入适配 JSON。
6. 新软件组进入窗口校准向导后，打开目标软件、选择窗口并保存绑定；已有软件可从「适配与文件绑定」打开向导。分项验证可按实际状态执行，也可暂时跳过。

关闭启幕窗口会保留托盘服务，方便下一次更快打开动画；托盘菜单可以完整退出。程序不默认注册开机自启。

## 三种启动行为

| 软件状态 | 行为 |
| --- | --- |
| 新软件组首次需要动画 | 播放完整开场，已有后台进程继续使用 |
| 没有运行 | 播放该软件组的冷启动动画，并启动软件 |
| 进程在后台、主窗口已关闭或隐藏 | 播放该软件组的恢复动画，并恢复窗口 |
| 窗口仍打开，包括最小化 | 直接置前或还原，不重播动画 |

已升级的 5 套主题使用连续 MP4 人物或场景动画及循环视频背景，其余主题保留现有的实时演出。每个软件组的三份素材独立保存，整套选择同一视频主题可匹配片尾与背景相位。导入格式支持 MP4、WebM、GIF、PNG、JPG、JPEG、WebP，单文件最大 64 MB。静态图片不会自动生成人物动作；自定义动态背景请选择已有视频或 GIF。

## 自动检测与兼容范围

窗口校准适用于可读取程序路径的标准 Windows 顶层窗口。列表不包含启幕自身、桌面宿主、更新／修复工具、Chromium 辅助进程和尺寸过小的工具窗口。无法读取高权限窗口时会跳过，需让启幕与目标软件使用相同权限。没有独立 EXE 归属的宿主窗口、复杂多进程窗口或不支持后台恢复的软件仍可能需要专门适配，不承诺所有应用都兼容。

- Codex：内置当前官方 Windows Store 版本的窗口与背景适配，更新安装路径后可重新发现。
- WorkBuddy：核对 `WorkBuddy.exe` 的产品、厂商信息和应用包结构，使用启幕编译内置的确认规则；保留的 `resources/adapters/workbuddy.json` 只作规则参考，不作为背景授权入口。软件升级后仍需验证实际页面。
- DoubaoWork：保留根目录 `DoubaoWork.exe` 启动入口，单独监测 `app/DoubaoWork.exe` 的真实主进程与窗口；支持外部启动动画，当前不支持内部背景。
- 其他 Electron 软件：框架识别用于启动和窗口监测，内部背景统一禁用；只能在后续启幕版本加入内置确认适配后开放。
- 普通 Windows EXE：支持外部启动动画；没有通用机制改写所有原生软件的内部背景，因此界面明确禁用该能力。后台恢复还取决于目标软件是否支持再次运行 EXE 恢复原实例。

首次接入背景时，如果软件此前由原快捷方式启动且未提供可验证的调试入口，需要先保存工作并正常完整退出目标软件，再从启幕快捷方式启动。启幕不会强行结束你的软件进程。多窗口 Electron 软件可在「适配与文件绑定」中指定主窗口标题与页面前缀。

原来的 `Codex Animation` 入口保留；新入口名称包含「启幕」，便于区分。请使用新入口验证新管理器。

## 绑定和修改的文件

| 文件 | 用途 | 操作 |
| --- | --- | --- |
| 软件启动 EXE、窗口监测 EXE（可为不同文件） | 分别启动软件、核对窗口与主进程归属 | 绑定，不改写 |
| `resources/app.asar`、`resources/app/package.json`、`resources.pak` 等 | 判断是否为 Electron | 检测存在，不改写安装文件 |
| 用户选择的适配 JSON | EXE、参数与窗口规则 | 读取并保存；不能授予背景权限，页面规则由启幕内置适配管理 |
| `%APPDATA%/LaunchCanvas/profiles.json` | 软件组配置 | 写入启幕自己的目录 |
| `%APPDATA%/LaunchCanvas/assets/` | 导入媒体的独立副本 | 写入启幕自己的目录 |
| `%APPDATA%/LaunchCanvas/runtime/`、`launch.log` | 本机启动状态和诊断 | 写入启幕自己的目录 |
| `%APPDATA%/LaunchCanvas/runtime/<软件组 ID>.calibration.json` | 当前配置的窗口绑定确认与四项验证结果 | 写入启幕自己的目录，移除软件组时清除 |
| 桌面 `.lnk` | 软件组启动入口 | 点击「发送到桌面」时创建 |

背景通过目标页面的本机接口运行，不修改目标 EXE、ASAR 或安装目录的样式文件。接口使用回环地址，接入前通过 Windows 监听表检查端口归属与 EXE 路径。不会上传素材，也不读取聊天内容。

卸载默认保留个人配置和素材，方便重装；手动创建的软件组快捷方式可自行删除。

## 适配配置

参考 `examples/electron.launchcanvas.json`。`executable` 可使用相对 JSON 所在目录的路径；`windowTitle` 是标题包含规则。`pagePrefix` 与背景 `selectors` 仅为旧格式兼容字段，不能通过导入自定义规则开放背景；已确认软件会使用启幕内置的页面规则。

独立启动器可额外填写 `windowExecutable`（相对 JSON 所在目录或绝对 EXE 路径），实际窗口程序使用 Chromium 多进程模型时填写 `processModel: "chromium"`。这些字段只控制窗口监测，不会更改启动入口或提升背景能力。例如：

```json
{
  "version": 1,
  "name": "DoubaoWork",
  "executable": "D:/file_address/DoubaoWork/DoubaoWork.exe",
  "windowExecutable": "D:/file_address/DoubaoWork/app/DoubaoWork.exe",
  "processModel": "chromium",
  "framework": "native"
}
```

校准导出的适配 JSON 还包括可选 `windowClass`（Windows 窗口类型的精确匹配值）和 `windowTitle`（稳定标题片段）。不要手工填写会随聊天或文件名改变的完整标题。验证记录属于本机实际运行结果，不随 JSON 导出；在另一台电脑导入后应重新验证。

软件安装目录不能可靠地推断所有应用的页面结构，因此背景仅向启幕内置确认的软件开放。其他软件仍可使用外部启动动画与窗口校准。上方较早版本的「待验证」与通用背景接入描述是历史记录，以 1.7.2 的名单策略为准。
